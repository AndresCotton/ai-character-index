Use the tool

The spec reader you are browsing is an open tool, and this site is its shipped example. Everything needed to run it yourself -- on your own behaviours, your own documents -- lives in the GitHub repository. This page is the short version of its README.

What the tool is

A tool for researchers working in the model-spec space. Point a panel of LLM judges at a specification -- Anthropic's constitution, OpenAI's Model Spec, or a document of your own -- and give the panel a behaviour you care about. You get back a passage-level coverage map: every place the spec addresses that behaviour, scored by each judge and quoted verbatim, browsable in a local copy of this reader.

The repository ships with a complete bench out of the box -- ten behaviours judged against both bundled specs by a three-judge frontier panel. That bench is what this site shows, so you can explore an example with results before running anything yourself.

What people use it for

  • Assess coverage. How well does a spec address a behaviour you are interested in? Is it a defining commitment, a passing mention, or a gap?
  • Locate the exact text. Every verdict anchors to a specific passage, so you see precisely where in the spec a behaviour is addressed.
  • Select passages for downstream work. Every citation is a stable, re-resolvable locator plus a verbatim quote, in plain JSON -- ready to feed automated adherence evals testing whether models actually follow the passages you selected.
  • Experiment with spec edits. Register your own spec versions locally, run the panel against each, and compare how coverage shifts as you rewrite.

Get it

The tool lives at github.com/AndresCotton/ai-character-index -- clone it, fork it, adapt it. Python 3.10+ and a browser are the only requirements; there is no Node.js and no build step.

git clone https://github.com/AndresCotton/ai-character-index.git
cd ai-character-index
python3 -m http.server 8080 --directory site

That is enough to browse the shipped results locally, no API keys needed. Running new judging takes exactly one key (OpenRouter). From there the README is the living documentation: registering a behaviour of your own, running the panel, reading the scores, bringing your own spec, and customizing the judge prompt.

Prefer to delegate? Everything from there on can be done by a coding agent: open one in the clone and say “register a behaviour about X and run the panel against both specs”. The repository ships agent instructions (AGENTS.md) carrying the same steps and their gotchas.
